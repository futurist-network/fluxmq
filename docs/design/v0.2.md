# FluxMQ v0.2 design — SDK reconnect, RBAC, routing, cluster

Status: implemented (v0.2). §7 lists the contract decisions made during integration. Contracts live in code:
`fluxmq-proto::{auth, routing, cluster, wire}`, `fluxmq-meta`, and the skeleton public APIs of
`fluxmq-auth`, `fluxmq-router`, `fluxmq-replication`, `fluxmq-cluster`. Read those module docs
first — this file explains how they fit together and who owns what.

## 1. Metadata store (`fluxmq-meta`) — the backbone

All cluster-wide state is a revisioned key → JSON map behind `MetaStore`:

| Key prefix | Owner | Content |
|---|---|---|
| `auth/tokens/<id>` | fluxmq-auth | `StoredToken` (TokenInfo + sha256 of secret) |
| `routes/<id>` | fluxmq-router | `Route` |
| `cluster/nodes/<id>` | fluxmq-cluster | node registry (addresses, version) |
| `cluster/channels/<name>` | fluxmq-cluster | `ChannelConfig` (cluster mode only) |
| `cluster/assignments/<name>` | fluxmq-cluster | `Vec<PartitionAssignment>` |

Single node: `LocalMetaStore` (`data_dir/meta.json`). Cluster: the Raft state machine.
Subsystems never know which; they watch for changes and react.

## 2. RBAC (stage 7) — `fluxmq-auth` + api + server

* Roles viewer ⊂ operator ⊂ admin, plus per-token data-plane `scopes` (channel globs).
* Bootstrap `--admin-token` stays (never stored). Open mode iff no bootstrap token and no tokens.
* HTTP: one central permission table in `fluxmq-api/src/auth.rs` maps (method, path pattern) →
  `Action`; the middleware authenticates, authorizes, and puts the `Principal` into request
  extensions so handlers record the real actor in the audit log. WS requires `Read`.
  New routes: `GET/POST /api/auth/tokens`, `DELETE /api/auth/tokens/{id}`, `GET /api/auth/me`.
  Errors: 401 unauthenticated, 403 forbidden (`error: "forbidden"`).
* Client protocol: `Hello.auth_token` → Principal per connection; each request authorized
  (`Publish(channel)`, `Consume(channel)`, `CreateChannel`); `ErrorCode::Forbidden`.
* UI: Settings → Access tokens (create with role/scopes/ttl, show secret once, revoke), role-aware
  actions (hidden/disabled with tooltip for insufficient role), `GET /api/auth/me` on start.

## 3. Routing (stage 8) — `fluxmq-router` + api + UI

* Rule engine = filter DSL + structured `Condition`s (`fluxmq_proto::routing`).
* Execution: router worker per source channel = consumer group `$router` (never on the publish
  path; lag/health visible like any group; failures → retry → DLQ with group `$router`).
* Loop protection via `flux-route-path`, max 8 hops.
* Backtest (`POST /api/routes/test`) scans stored messages (cap 200k) for "Matched last 24h".
* The same filter powers message search: `GET /api/channels/{name}/messages?filter=…`
  (scan-based with the existing scan cap — no payload index in v0.2).
* HTTP: `GET/POST /api/routes`, `GET/PATCH/DELETE /api/routes/{id}`, `POST /api/routes/test`,
  `GET /api/routes/stats`, `POST /api/filter/parse`.
* UI: global Routing page + channel "Routing" tab; WHEN/THEN editor (structured rows ⇄ DSL text),
  live backtest preview, per-route stats; Messages search accepts the filter DSL.

## 4. Cluster (stage 9) — `fluxmq-cluster` + `fluxmq-replication` + core + server

**Metadata/consensus:** openraft 0.9.x on every node (voters = initial peers, later joiners are
learners until promoted). Raft leader = controller. Raft RPC transport: HTTP/JSON or framed TCP on
`--raft-addr` (default 7422) — owner's choice, internal only.

**Assignment:** controller writes `cluster/assignments/<channel>` for new channels (RF =
min(replication_factor, live nodes), leaders spread round-robin, preferred leader = first
replica). Every node watches assignments and calls `ReplicationManager::set_role` for each
partition it replicates, and creates/deletes local channel storage to match
`cluster/channels/*`.

**Data replication (Kafka-style):** followers pull from partition leaders on
`--replication-addr` (default 7423). Leader tracks follower LEO → ISR (evict after
`replica_lag_max`) → HW = min LEO over ISR. Publish ack waits for HW ≥ last offset (acks=all) on
top of the local fsync policy; `min_isr` violated → error `NotEnoughReplicas` (wire `Overloaded`
with message). Consumers only receive offsets < HW. Group committed offsets and DLQ mutations are
replicated as part of the fetch stream (state records), so a new leader resumes consumption from
the last replicated offsets (at-least-once). Retry timers/in-flight state are not replicated —
unacked messages are redelivered after failover. Attempt history is local.

**Failover:** node liveness by heartbeat into Raft (or Raft membership health); controller marks
a node `Down` after `node_timeout` (default 6 s), picks a new leader for each affected partition
from the ISR (prefers preferred replica), bumps `epoch`, writes assignments. New epoch fences the
old leader: on rejoin it truncates to the new leader's HW for that epoch, then follows.
`offline_partitions` = partitions with no ISR member alive (no unclean election in v0.2).

**Client routing:** wire v2 adds `Metadata`, partition-targeted `Publish`, `NotLeader`,
`MetadataChanged`. A node receiving `Publish{partition: None}` forwards each message to its
partition leader (server-side proxy, keeps naive clients working). The SDK fetches metadata,
partitions client-side with the same function as core (`crc32(key) % P`, round-robin without key),
sends directly to leaders, and for consumption opens a subscription on every node that leads ≥ 1
partition of the channel (each node serves only partitions it leads; group assignment per node is
deterministic over the instances connected to it).

**HTTP in a cluster:** any node serves the UI/API. Reads that need partition data (messages, DLQ,
message detail) fan out to partition leaders over internal HTTP (`/internal/v1/*`, authenticated
with a cluster secret `--cluster-secret`); metadata mutations go through the controller; channel
create/delete go through `Cluster::create_channel/delete_channel`.

**Telemetry in a cluster:** each node computes its local documents as today; the node serving a
browser additionally pulls compact node stats from peers (`/internal/v1/node-stats`, every 1 s)
and merges them into cluster-wide `cluster.overview`, `channels.summary`, `nodes` (sum rates, max
lag, merged histograms). Prometheus text exposition at `GET /metrics` on every node (node-local).

**Config (server flags / env):** `--node-id`, `--peers id@raft_host:port,…`, `--raft-addr`,
`--replication-addr`, `--advertise-host`, `--replication-factor` (default 3, capped), `--min-isr`
(default 1), `--cluster-secret`. No `--peers` → single node (v0.1 behaviour, unchanged).

## 5. SDK (`fluxmq-client`)

* Reconnect with exponential backoff + jitter; multiple seed addresses; re-handshake.
* Consumers transparently resubscribe (same group) after reconnect / `MetadataChanged`; in-flight
  deliveries from the dead connection are dropped (broker redelivers — at-least-once).
* Publish: retry on connection loss / `NotLeader` / `Unavailable` up to a deadline
  (`publish_timeout`), refreshing metadata between attempts. Documented: retries can duplicate.
* Cluster-aware: metadata cache, client-side partitioning, direct-to-leader publish, per-node
  consumer subscriptions. Works unchanged against a single node.
* Connection state observable (`Client::state()` watch: Connecting/Connected/Reconnecting/Closed).

## 7. Contract decisions made during integration

* `ApiError.position: Option<usize>` (omitted when `None`): byte offset of a filter DSL syntax
  error (`filter=` on message search, `POST /api/filter/parse`). The UI underlines from it.
* `POST /api/filter/render` (`{conditions}` → `{rendered}`, viewer): the editor's builder → text
  direction. `ui/src` contains no DSL implementation; the mock keeps its own port.
* `Condition.value`: an explicit JSON `null` is the value `null` (round-trips parse → render).
* `CreateTokenResponse.adopt: bool` — true when the token switched the broker from open to
  enforced; the first token in open mode must be `admin` (else 400); names `admin`/`anonymous`
  are reserved.
* `ClusterOverview.nodes_up` (status-based: members not `down`) next to `nodes_healthy`; the UI
  shows "N/M nodes up" from it and colours by `health`.
* `RouteStats.forwarded`/`failed` count per target; routes apply only to messages published
  after the route exists; payload fields named `key`/`partition` need the `payload.` prefix;
  DLQ export = operator, `GET /api/auth/tokens` = admin, every other `GET` = viewer.
* `DELETE /api/channels/{name}/groups/{group}` (admin; 409 with active consumers; `$router` only
  while no route uses the channel). Deleting a source's last route releases its `$router` group.
* Cluster: replay and DLQ export fan out to partition leaders with the same partition-coverage
  check as message reads; graceful shutdown = `Drain` + `ControllerOp::Leave` (node marked
  `Down`, dropped from every ISR at once).
