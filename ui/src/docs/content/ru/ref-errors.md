## REST API {#http}

Ошибка — не-2xx ответ с телом `{"error": "<код>", "message": "<текст>"}`. Ветвитесь по `error`, а не по `message`. У синтаксических ошибок фильтра есть ещё `position` — смещение ошибки в байтах.

```json
{"error":"bad_request","message":"filter syntax error at 8: unexpected character '~'","position":8}
```

| HTTP | `error` | Значит | Что делать |
|---|---|---|---|
| 400 | `bad_request` | неверный запрос: имя, параметры, синтаксис фильтра, SSRF-запрет адреса вебхука | исправьте запрос по тексту `message` |
| 400 | `unsupported_in_cluster` | операция не может выполниться в этом кластере (например, бэкап при узле старше 0.3.0) | обновите узлы |
| 400 | `unsupported_single_node` | кластерная операция на одиночном узле (ребалансировка, вывод узла) | только для кластера |
| 401 | `unauthorized` | токена нет, он неверный или истёк | передайте действующий `Authorization: Bearer …` |
| 403 | `forbidden` | токен верный, но роли или областей действия не хватает | нужна роль выше — см. [роли](/docs/access-tokens#roles) |
| 404 | `not_found` | канала, группы, маршрута, узла… нет | проверьте имя или id |
| 409 | `conflict` | конфликт состояния: канал уже есть, группа с получателями, идёт другой план или бэкап, параллельное изменение | дождитесь окончания или устраните причину из `message` |
| 409 | `last_admin` | попытка отозвать последний токен администратора | сначала выпустите другой токен администратора |
| 503 | `unavailable` | временно недоступно (например, история уведомлений без лидера раздела) | повторите позже |
| 500 / 503 | `internal` | внутренняя ошибка или временная недоступность (смена лидера, нет кворума метаданных) | повторите; 503 «partitions … are changing leaders; retry» проходит за секунды |

## Клиентский протокол {#wire}

Ошибки ответа брокера (`ErrorCode`) в SDK приходят как `ClientError::Server`:

| Код | Значит | SDK повторяет? |
|---|---|---|
| `BadRequest` | неверный запрос (в том числе `nack` в режиме cumulative, неизвестная версия протокола у старого брокера) | нет |
| `Unauthorized` | нет или неверный токен при подключении | нет |
| `Forbidden` | не хватает роли или областей действия; соединение не рвётся | нет |
| `NotFound` | канала нет (в кластере повторяется, пока метаданные ещё знают канал) | нет |
| `AlreadyExists` | канал уже существует | нет |
| `NotLeader` | узел не лидер раздела (в `message` — id лидера) | да, обновив метаданные |
| `Overloaded` | брокер перегружен или в ISR меньше `--min-isr` реплик («not enough replicas») | да |
| `ProtocolViolation` | нарушение протокола, например открытый текст на TLS-порту: `this port requires TLS` | нет |
| `Internal` | внутренняя ошибка брокера | — |

Ошибки самого SDK (`ClientError`): `Io` (сеть, в том числе `TLS handshake with …`), `Protocol` (например, `TLS configuration: …` при неверных путях к сертификатам), `Server(…)` (коды выше), `Timeout` (истёк `request_timeout`), `Closed` (клиент закрыт или исчерпал попытки переподключения). Публикации повторяются при обрыве, таймауте, `NotLeader` и `Overloaded` до `publish_timeout`.

## Закрытие сессий {#sessions}

| Где | Код / причина | Значит |
|---|---|---|
| Клиентский протокол | `Goodbye` «token revoked» / «token expired» | токен отозвали или истёк срок |
| Клиентский протокол | `Goodbye` «certificate binding revoked» | удалена привязка сертификата |
| Клиентский протокол | `Goodbye` при остановке брокера | штатная остановка; SDK переподключится |
| WebSocket консоли | код **4401** | токен сессии отозван или истёк — консоль попросит новый |

## Ошибки доставки (DLQ, вебхуки, уведомления) {#delivery}

Короткие классы причин: `HTTP <код>`, `timeout`, `connection refused`, `connection failed`, `DNS error`, `TLS error`, `blocked by policy` (SSRF), `SMTP <код>`, `route target unavailable: <канал>`. Полный текст — в `error_detail` / `last_error_detail` и во всплывающих подсказках консоли.
