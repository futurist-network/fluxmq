**Отложенное сообщение** — сообщение, которое брокер публикует в канал не сразу, а в заданное время. Примеры: напоминание через сутки, повтор оплаты через час, «отменить заказ, если не оплачен до 18:00». Своя очередь таймеров, cron или отдельный сервис для этого не нужны.

## Как это устроено {#how}

- Сообщение с задержкой сразу записывается на диск (и на копии в кластере) в системный канал `$scheduled`. Отправитель получает подтверждение после записи, как при обычной публикации.
- В срок брокер публикует его в целевой канал. Дальше это обычное сообщение: получатели, повторы, DLQ, маршруты и вебхуки работают как всегда.
- Точность — около 100 мс. Если брокер был выключен в момент срока, сообщение уйдёт сразу после запуска.
- Задержка — не больше **30 дней**. Время в прошлом — значит «отправить сейчас».
- В памяти брокер держит только время и номер каждого ожидающего сообщения (около 100 байт), а содержимое читает с диска в момент отправки. Поэтому миллион отложенных сообщений не нагружает систему.
- Порядок по ключу — порядок отправки в срок: сообщения с одним ключом и одним временем уходят в том порядке, в котором были запланированы.

> [!NOTE]
> Гарантия — «хотя бы один раз». Если узел упадёт ровно между публикацией и отметкой «отправлено», после восстановления сообщение может уйти повторно. У обеих копий одинаковый заголовок `flux-scheduled-id` — по нему получатель распознает повтор.

## Как отправить {#send}

**Консоль:** на странице канала кнопка **Отправить сообщение** → **Когда**: «Сейчас», «Через…» (секунды, минуты, часы, дни) или «В момент…» (дата и время). Нужна роль оператора.

**SDK (Rust):**

```rust
producer.send(message(body).delay(Duration::from_secs(600))).await?;   // через 10 минут
producer.send(message(body).deliver_at(nine_am)).await?;                // в 9:00
```

**REST:** поле `delay_ms` (миллисекунды от сейчас, по часам брокера) или `deliver_at_ms` (unix-время в мс):

```bash
curl -X POST $FLUXMQ/api/channels/orders/publish -H 'content-type: application/json' \
  -d '{"messages":[{"key":"ord-8842","payload":{"encoding":"utf8","data":"{\"order_id\":8842}"},"delay_ms":3600000}]}'
```

**Любой клиент:** заголовок `flux-delay-ms` или `flux-deliver-at`.

Вернувшийся номер сообщения — его номер в расписании (`партиция/смещение` в `$scheduled`). По нему сообщение можно отменить или отправить сразу. После отправки у сообщения появляется обычный номер в канале и заголовки `flux-scheduled-id` и `flux-scheduled-for`.

## Страница «Отложенные» {#page}

| Блок | Что показывает |
|---|---|
| Ждут отправки | сколько сообщений запланировано и в скольких каналах |
| Ближайшая отправка | когда уйдёт следующее |
| Отправлено / Отменено | счётчики с запуска узлов |
| Фильтр по каналу | только сообщения выбранного канала |
| Скоро отправятся | ближайшие сообщения по всем узлам: когда, канал, тип и ключ, размер, когда запланировано |

Действия (роль оператора): **Отправить сейчас** публикует сообщение немедленно, **Отменить** — оно не будет доставлено.

## REST {#rest}

| Метод и путь | Что делает | Роль |
|---|---|---|
| `GET /api/scheduled?channel=&limit=` | ближайшие отложенные сообщения (по умолчанию 100, максимум 1000), счётчики по каналам | R |
| `DELETE /api/scheduled/{partition}/{offset}` | отменить | O |
| `POST /api/scheduled/{partition}/{offset}/release` | отправить сейчас | O |

Если сообщение уже отправлено или отменено, ответ — 404.
