**Живая подписка** — чтение канала в реальном времени по WebSocket или SSE прямо с HTTP-порта брокера (`7421`). Подходит для браузеров, мобильных приложений и устройств: не нужны SDK, отдельный бэкенд и постоянное соединение по клиентскому протоколу.

- Подписка **только читает**: группа получателей не создаётся, ничего не подтверждается, другие получатели ничего не замечают.
- Видно ровно то, что увидел бы обычный получатель: только подтверждённые, надёжно записанные сообщения.
- После обрыва подписка продолжается **по курсору** без потерь и без повторов.
- Одно общее чтение на канал: тысяча подписчиков одного канала стоит брокеру одного чтения диска.

Включать ничего не нужно — подписки работают сразу. Настраиваются только лимиты (флаги `--live-*`).

## Как подключиться {#connect}

1. **Токен.** Для браузера создайте токен с ролью **«Подписчик»** (*Настройки → Токены доступа*) и укажите каналы в поле «Живые подписки на». Такой токен не может ничего, кроме подписок на эти каналы. Выдавайте короткоживущие токены со своего бэкенда, по одному на пользователя. Наблюдатель и роли выше могут подписываться на любой канал.
2. **Код.** Готовый код с подставленным каналом — на вкладке канала **«Живые подписки»** и на странице **Живые подписки**.
3. **Другой сайт.** Страницы с того же адреса, что и брокер, работают сразу. Чужие сайты по умолчанию не пускаются (проверка `Origin`); разрешить: `--live-allowed-origins https://app.example.com`.

```js
// SSE: проще всего; браузер сам переподключается и продолжает с места обрыва
const es = new EventSource('/api/channels/orders/events?from=latest&key=user_42&access_token=' + token);
es.addEventListener('messages', (e) => {
  for (const m of JSON.parse(e.data).messages) console.log(m.offset, m.payload);
});

// WebSocket: несколько подписок в одном соединении; токен — во втором подпротоколе
const ws = new WebSocket(`wss://${location.host}/api/channels/orders/live?from=earliest`,
                         ['fluxmq.live.v1', 'fluxmq.token.' + token]);
ws.onmessage = (e) => {
  const ev = JSON.parse(e.data);           // hello | messages | gap | reset | progress | error
  if (ev.cursor) localStorage.cursor = ev.cursor;   // для продолжения: ?cursor=...
};
```

Серверам и скриптам проще передавать токен заголовком `Authorization: Bearer …` — он работает на обоих адресах.

## Параметры {#params}

| Параметр | Что делает |
|---|---|
| `from` | откуда читать: `latest` (по умолчанию, только новые), `earliest`, `time:<unix ms>`, `offsets:0=10,1=20` |
| `cursor` | продолжить с позиции из последнего события — без потерь и повторов; важнее `from` |
| `key` | только сообщения с этими ключами: `key=user_42` или `key=a,b` |
| `header.<имя>` | равенство заголовка: `header.type=order.created` |
| `filter` | выражение на [языке фильтров](/docs/ref-filter): `amount >= 100 AND country = "DE"` |
| `partitions` | только эти разделы: `0,2` |
| `access_token` | только SSE: токен в адресе (`EventSource` не умеет заголовки) |

Фильтрует сервер; отфильтрованные сообщения всё равно сдвигают курсор (событие `progress`).

## События {#events}

| Событие | Когда |
|---|---|
| `hello` | подписка открыта; в нём стартовый курсор и лимиты |
| `messages` | пачка сообщений: раздел, offset, ключ, заголовки, время, содержимое |
| `gap` | часть сообщений удалена по сроку хранения раньше, чем их успели отправить (`lost` — сколько) |
| `reset` | позиция оказалась за концом журнала (узел восстановлен из копии) — чтение продолжается с конца |
| `progress` | фильтр пропустил сообщения, курсор сдвинулся |
| `error` | неверная команда или подписка отклонена |
| `end` | только SSE: сервер закрывает поток (`slow`, `revoked`, `deleted`, `limit`, `shutdown`) |

Содержимое больше `--live-max-payload-bytes` (64 КиБ) обрезается и помечается `truncated: true` — целиком его можно получить через REST.

## Вкладка канала {#live-tab}

На странице канала вкладка **«Живые подписки»** показывает:

- сколько подписок открыто на канал прямо сейчас (по всем узлам) и лимит на канал;
- **Попробовать** — настоящая подписка из браузера с токеном консоли: сообщения появляются по мере записи в канал. Только чтение — получатели и их позиции не меняются;
- **Код** — готовый код для SSE, WebSocket и curl с выбранными параметрами (начать с, ключи, фильтр); токен в нём всегда заглушка `TOKEN`.

## Страница «Живые подписки» {#page}

| Блок | Что показывает |
|---|---|
| Соединения | открытые соединения WebSocket и SSE |
| Подписки | в реальном времени и догоняющие (ещё читают историю) |
| Каналы с подписчиками | на какие каналы подписаны сейчас и какая доля лимита занята |
| Отказы | сколько подключений не пустили и почему: лимиты, чужой сайт, нет прав, нет токена |
| Медленные / пропуски | клиенты, закрытые за то, что не успевали принимать, и подписчики, которые потеряли сообщения из-за срока хранения |
| Лимиты | значения флагов `--live-*` на каждом узле |

Счётчики считаются с запуска узла. Те же данные есть в метриках `fluxmq_live_*` (`/metrics`) и в REST: `GET /api/live/status`.

## Лимиты {#limits}

| Флаг | По умолчанию | Что ограничивает |
|---|---|---|
| `--live-max-connections` | 10000 | соединений на узел; сверх — 503 |
| `--live-max-connections-per-token` | 1000 | соединений на токен; сверх — 429 |
| `--live-max-connections-per-channel` | 10000 | подписок на канал на узле; сверх — 429 |
| `--live-max-subscriptions` | 16 | подписок в одном WebSocket |
| `--live-max-msgs-per-sec` | 10000 | сообщений в секунду на соединение (притормаживает, не теряет) |
| `--live-max-bytes-per-sec` | 16 MiB | байт в секунду на соединение |
| `--live-send-timeout` | 10 с | сколько ждать медленного клиента, прежде чем закрыть |
| `--live-allowed-origins` | — | какие чужие сайты пускать (`*` — любые) |

Полный список — в [справочнике CLI](/docs/ref-cli).

> [!NOTE]
> Брокер не теряет сообщения из-за медленного клиента: лимиты скорости притормаживают отправку, а клиента, который совсем не принимает, закрывают. После переподключения с курсором он получит всё, что пропустил, — пока сообщения хранятся.
