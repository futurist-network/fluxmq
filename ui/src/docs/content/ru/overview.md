FluxMQ — брокер сообщений на Rust. Один бинарник `fluxmq` хранит сообщения на диске, раздаёт их потребителям с подтверждениями и повторами, сам считает метрики и оповещения (алерты) и сам же отдаёт эту веб-консоль. Отдельный Prometheus, Grafana или админка не нужны, чтобы увидеть, что сломалось, и исправить это.

## Что умеет {#features}

- **Каналы (топики) трёх режимов** — `stream` (перечитываемый лог, как топик Kafka), `queue` (конкурирующие воркеры, как очередь RabbitMQ) и `keyed` (строгий порядок по ключу). Подробно — в статье [Основные понятия](/docs/concepts).
- **Надёжная доставка** — at-least-once, подтверждение каждого сообщения, повторы с backoff, **очередь недоставленных (DLQ)** с группировкой по причине ошибки.
- **Долговечность по умолчанию** — публикация подтверждается только после `fsync` на диск (group commit), а в кластере — после репликации на все синхронные реплики (ISR).
- **Наблюдаемость встроена** — скорости, перцентили задержек, отставание групп, правила здоровья и оповещения считает сам брокер; консоль получает готовые агрегаты по одному WebSocket.
- **Кластер** — метаданные в Raft, репликация разделов как в Kafka, автоматический failover, ребалансировка, вывод узлов.
- **Эксплуатация** — токены доступа и роли (RBAC), TLS и mTLS на всех портах, маршрутизация по содержимому, HTTP-вебхуки, уведомления (Telegram, Slack, Discord, email, PagerDuty, вебхук), бэкапы в S3 или на диск, метрики Prometheus.

## Архитектура в одной схеме {#architecture}

:::diagram architecture

- **Порт 7420** — бинарный клиентский протокол: отправители (producers) и получатели (consumers) — Rust SDK `fluxmq-client`.
- **Порт 7421** — HTTP: REST API `/api/*`, телеметрия по WebSocket `/ws`, метрики `/metrics` и сама консоль.
- **Порты 7422 и 7423** — только в кластере: Raft (метаданные, выбор контроллера) и репликация данных разделов.

Главное правило устройства: **плоскость наблюдения никогда не тормозит плоскость данных**. Ядро только накапливает счётчики, а телеметрия забирает их сама; живые потоки (события, live tail) идут через ограниченные буферы и при перегрузке прореживаются, а не задерживают публикации.

## Как читать эту документацию {#how-to-read}

- **Начало работы** — понятия, первый запуск и навигация по консоли.
- **Разделы консоли** — по статье на каждый экран: что показано, что означает каждая цифра, что нормально, а что — проблема, и какие действия доступны.
- **Как сделать** — пошаговые сценарии: создать канал, подключить клиента, разобрать отставание или DLQ, настроить уведомления, защитить брокер, обновить кластер.
- **Справочник** — флаги и переменные окружения, REST API, метрики Prometheus, коды ошибок, язык фильтров, глоссарий.

> [!TIP]
> На любом экране консоли кнопка «?» открывает статью именно про этот экран. Поиск слева ищет по заголовкам и тексту всех статей; клавиша <kbd>/</kbd> переводит в него фокус.

## Ограничения текущей версии {#limits}

FluxMQ подходит для разработки и пилотной эксплуатации. Чего пока нет: индекса по полям payload (поиск сканирует до 200 000 сообщений за запрос), оператора `OR` в фильтрах, экспорта в OpenTelemetry, rack/AZ-awareness, планировщика ребалансировки по байтам, одновременного вывода нескольких узлов, перечитывания CA без перезапуска, CRL/OCSP, восстановления бэкапа сразу в кластер и SSO. Официальный SDK пока только для Rust.
