| Термин | English | Что значит |
|---|---|---|
| Канал (топик) | channel | именованный поток сообщений; аналог топика Kafka или очереди RabbitMQ |
| Режим канала | mode | `stream` (поток), `queue` (очередь) или `keyed` (по ключу) — см. [Основные понятия](/docs/concepts#modes) |
| Раздел (партиция) | partition | часть канала со своим упорядоченным логом; единица параллелизма и репликации |
| Смещение | offset | номер сообщения в разделе; позиция группы — смещение, до которого она дочитала |
| Отправитель | producer | сервис, который публикует сообщения |
| Получатель | consumer | сервис, который читает сообщения |
| Группа получателей | consumer group | именованный читатель канала; каждая группа получает все сообщения, экземпляры внутри группы делят работу |
| Экземпляр | instance | одна запущенная копия получателя в группе |
| Подтверждение | ack | сигнал «сообщение обработано» |
| Отказ | nack | сигнал «не обработано» с причиной: повторить или сразу в DLQ |
| Prefetch | prefetch | сколько неподтверждённых сообщений может одновременно быть у экземпляра |
| Тайм-аут подтверждения | ack timeout | время, после которого доставка без подтверждения считается неудачной попыткой |
| Повтор, пауза | retry, backoff | повторная доставка после неудачи и пауза перед ней |
| Очередь недоставленных (DLQ) | dead-letter queue | куда попадают сообщения, исчерпавшие попытки, вместе с причиной |
| Отставание | lag | сколько сообщений группа ещё не обработала |
| Хранение | retention | сколько времени / объёма канал хранит сообщения |
| Сегмент | segment | файл лога раздела; хранение удаляет сегменты целиком |
| Переигрывание | replay | публикация копии сохранённого сообщения в канал |
| Сброс смещений | reset offsets | перенос позиции группы на начало, конец или момент времени |
| Маршрут | route | правило копирования подходящих сообщений в другие каналы |
| Вебхук | webhook | доставка сообщений канала POST-запросами на HTTP-адрес |
| Оповещение | alert | проблема, обнаруженная правилами здоровья брокера |
| Событие | event | факт: канал создан, получатель отключился и т. п. |
| Канал уведомлений | notifier | куда отправлять оповещения: Telegram, Slack, email, PagerDuty… |
| Правило уведомлений | notification rule | какие оповещения и события куда отправлять |
| Узел | node | один процесс `fluxmq` в кластере |
| Контроллер | controller | узел — лидер Raft; раскладывает разделы и переключает их при сбоях |
| Лидер раздела, реплика | leader, replica | узел, принимающий запись раздела, и узлы с копиями |
| ISR | in-sync replicas | реплики, догнавшие лидера; публикация подтверждается, когда сообщение есть у всех |
| Недореплицированный раздел | under-replicated | в ISR меньше реплик, чем назначено |
| Недоступный раздел | offline | у раздела нет живого лидера |
| Фактор репликации | replication factor (RF) | сколько копий у каждого раздела |
| Снятие лидерства | drain | перенос лидерства разделов с узла перед обслуживанием |
| Вывод узла | decommission | перенос всех реплик и удаление узла из кластера |
| Ребалансировка | rebalance | восстановление и выравнивание размещения реплик |
| Токен доступа | access token | секрет `fmq_…` с ролью и областями действия |
| Роль | role | наблюдатель (viewer), оператор (operator), администратор (admin) |
| Области действия | scopes | маски каналов для публикации и чтения через клиентский протокол |
| Привязка сертификата | certificate binding | сопоставление CN клиентского сертификата с ролью |
| Пачка записей | record batch | формат 0.7: пачка сообщений, записанная и реплицируемая целиком |
| Group commit | group commit | объединение записей в пакеты с одним fsync перед подтверждением |
